# When to use

- Use for facts outside the conversation and the workspace: current prices, policies, competitors, papers, people, dates, standards.
- Use when a draft sentence makes an external claim and no source is attached yet.
- Do not use for arithmetic, definitions, or file contents. Check the workspace first, and say what you read before searching.

# Steps

1. **Sharpen the question.** Write up to three sub-questions, one line each, and name the decision each sub-question serves.
   - Validate: every sub-question can end as found with one source, or as not found with the search recorded; split or drop the rest.
2. **Plan queries before searching.** One focused query per sub-question, plus one disconfirming query for each claim that would change a recommendation.
   - Validate: the plan names at least one disconfirming query, and no query is a single generic word.
3. **Open what you will cite.** Run the searches, then open every page you intend to use, not only the result list.
   - Validate: a candidate survives only if its page body was read in this session.
4. **Grade the source.** Read `references/source-tiers.md` and assign a tier to each opened page.
   - Validate: every decision-grade claim cites tier 1 or tier 2 only; a tier 3 or 4 page is labelled weak or dropped.
5. **Log the source.** Write each kept source in the shape of `references/search-log.md`: title, opened URL, printed date, retrieval date, tier.
   - Validate: a page with no printed date is logged as `date not stated`; a row without an opened page is deleted, not completed.
6. **Handle disagreement.** When two sources disagree, keep both rows and mark which page is newer.
   - Validate: the disagreement reaches the answer as two rows, never as one chosen number.
7. **Hand off the log.** Cite at most five sources in prose; the evidence table carries the rest.
   - Validate: every citation in the answer has a log row, and every log row is cited or listed once.

# Refusals

- Never write a URL, page title, quote, or date that you did not read in this session. Write `not found` instead.
- Never treat a search-result snippet as the source. A snippet is a lead, not evidence.
- Never cite a page behind a sign-in you could not open. Name the blocker in one line.
- Never retry a failed fetch more than once. Report the failure and continue.
- Never fill a table cell from memory to avoid a gap. Write `not found` and say what was searched.
- Read-only: no purchases, posts, form submissions, or account changes while researching.
- Never store a password, token, or private identifier in a log or a table.

# Checks

1. Every external claim carries a citation with an opened URL and a retrieval date.
2. Every kept source has a tier and either a printed date or `date not stated`.
3. Every disagreement appears as two rows, and the newer one is marked.
4. Each sub-question ends as found or not found; none is left open silently.
5. No URL, quote, title, or date appears that was not read in this session.
